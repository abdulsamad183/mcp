Introduction to MCP

What the Model Context Protocol is, the mental model behind it, and why it exists.

What is MCP?

The Model Context Protocol (MCP) is an open communication standard that defines how AI applications — including LLM-powered chat interfaces, agents, and pipelines — connect to external tools, data sources, and services.

Think of MCP as a universal adapter. Just as USB-C standardised how devices connect to peripherals regardless of brand, MCP standardises how AI applications connect to capability providers regardless of which AI model or hosting platform they use.

Core idea
MCP shifts the responsibility of defining and executing tools away from your application and into dedicated, reusable MCP Servers — so you can focus on your application logic, not integration plumbing.

The mental model

When you first look at MCP you will see three distinct roles:

Role Who it is Responsibility
Host Application Your chat app, agent pipeline, or IDE plugin Drives the user interaction; decides when to call tools
MCP Client A library embedded in your application Speaks the MCP protocol; discovers and calls tools on servers
MCP Server A standalone process or service (often third-party) Owns tool definitions and executes them against external services

Key primitives

MCP Servers expose three types of capability to clients:

🔨

Tools

Callable functions with typed schemas — e.g. list_repositories(), create_issue(). The AI model decides when to call them.

📄

Resources

Read-only data the AI model can fetch — e.g. a file, a database row, a documentation page. Think of them as context the model can pull on demand.

💬

Prompts

Reusable, parameterised prompt templates stored on the server and made available to the host — enabling consistent, shareable instructions.

Why does MCP matter?

Before MCP every team building an AI feature that needed to access external services had to solve the same problem from scratch: write tool schemas, implement API wrappers, handle authentication, parse responses, and maintain all of that code over time.

MCP turns this into a solved problem. A single well-written MCP Server for a service (say, a project management tool) can be reused by any application, any AI model, and any team — with no additional integration work.

LLM Agnostic
MCP is not tied to any specific AI model or provider. Whether you are using an open-source model running locally or a hosted commercial API, the same MCP Servers work the same way.

A brief history

MCP was introduced by Anthropic in late 2024 and quickly adopted across the AI ecosystem. The specification is open, versioned, and maintained publicly. Any organisation — whether a cloud provider, a SaaS company, or an individual developer — can publish an MCP Server that others can plug straight into their AI applications.

Official specification
The canonical MCP specification lives at modelcontextprotocol.io and includes reference SDKs for TypeScript and Python.
